# Benchmark reports

The benchmark has two runnable Linux x86-64 targets: `linux-x86-avx2` and `linux-x86-scalar`. Each target has one command that checks bytes, measures the four selected modes, and writes one report.

## Run

Build the local data and peer tools first:

```sh
python3 tools/base64_data.py generate
python3 tools/peer_check.py --bench --reference tools/bin/aklomp-base64
```

Run either target from the repository root:

```sh
bash bench/linux-x86-avx2/run.sh
bash bench/linux-x86-scalar/run.sh
```

The default run uses 20 measured samples, 5 warmups, and a 15,000 ms Zebrac duration ceiling per group. Use `--runs`, `--warmup`, or `--duration` when a local check needs a different sample policy.

```sh
bash bench/linux-x86-avx2/run.sh --runs 5 --warmup 2 --duration 2000
```

Use `--skip-verify`, `--skip-benchmarks`, or `--skip-report` to repeat one part of an existing run. A publication report should use the default byte check and sample policy.

## Output

Each target folder keeps the report and the two tables that produced it:

- `REPORT.md` explains the commands, data, versions, host, sampling, caveats, and results.
- `measurements.tsv` contains one row for each measured command and input.
- `summary.tsv` contains the geometric means, case counts, and huge-input values used by the report.
- `figures/scaling.svg` shows throughput by size.
- `figures/isocost.svg` shows time and peak-RSS ratios to B64Z.

Raw encoded inputs and Zebrac JSON stay under the ignored `bench/work/` directory. The runner does not create a report for each input.

## Modes and peers

The four B64Z rows are `encode-memory`, `decode-memory`, `encode-streaming`, and `decode-streaming`. Memory peers are compared only with the memory rows. Aklomp and GNU Coreutils are compared only with the streaming rows because the selected executables expose streaming file commands.

All output bytes are checked before timing. The checks use the valid fixtures, B64Z invalid-input fixtures, every benchmark input, and the canonical padded bytes generated by Aklomp. A peer that accepts a wider invalid grammar is not used as an invalid-input comparison.

The timed command starts one process per sample, reads one input file, performs the selected operation, and writes to stdout. Zebrac discards stdout. File preparation and byte comparison happen before the timed groups.

## Requirements

The runner currently requires Linux x86-64, Zig 0.16.0, GNU gnuplot, the local peer binaries under `tools/bin/`, and Zebrac 0.6.2. It uses `ZEBRAC` when set, then `zebrac` on `PATH`, then `/home/eke/bin/zebrac`.

The target binaries are ignored under `bench/linux-x86-avx2/bin/` and `bench/linux-x86-scalar/bin/`. Reports and tables are not ignored, so the exact published run can be reviewed with the target folder.
